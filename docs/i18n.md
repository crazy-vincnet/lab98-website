# i18n (Korean + English)

Korean is the default locale and lives at the root (`/about`). English lives under `/en` (`/en/about`).
Both are fully static (Cache Components); no locale middleware, no cookies, no `Accept-Language` redirect (`src/proxy.ts` only refreshes the admin session on `/admin/**`).
Overview: [README](../README.md). Admin-editable copy (ko + en): [admin-content.md](admin-content.md).

## How it is wired

```
src/app/
  (ko)/                 root layout #1  <html lang="ko">   all Korean pages, URLs unchanged
  (en)/en/              root layout #2  <html lang="en">   all English pages  → /en/...
  (admin)/admin/       root layout #3  <html lang="ko">   back office, noindex (docs/admin.md)
  global-not-found.tsx  404 for unmatched URLs (needed with 2 root layouts; next.config experimental.globalNotFound)
  globals.css, styles.ts            shared CSS + fonts, imported by every root layout
  sitemap.ts robots.ts manifest.ts favicon.ico icon.png apple-icon.png
  llms.txt llms-full.txt insights/rss.xml actions/    shared, stay at the app root (URLs unchanged)
  opengraph-image.tsx twitter-image.tsx + <page>/opengraph-image.tsx …   Korean OG/Twitter cards, deliberately NOT inside (ko)
  en/opengraph-image.tsx en/twitter-image.tsx        generic English card
src/components/pages/   one module per page: xMetadata(locale) + XPage({ locale })   ← the real pages
src/components/site-shell.tsx   <html>/<body> + header + footer + cookie banner, used by both root layouts
src/lib/i18n.ts         Locale, localePath(), switchLocalePath(), stripLocale(), Dict<T>, OG_LOCALE …
src/lib/get-content.ts  getContent(locale) → { site, nav, divisions, projects, notes, faqs, … }   (code defaults, synchronous)
src/lib/site-content.ts getSiteContent(locale) → same shape + published admin overrides (async; use this for text)
src/lib/content.ts      Korean data + shared non-text helpers (divisionTheme, symbolSrc, formatDate, types)
src/lib/content.en.ts   English data (same exports/shapes)
```

Route files are thin on purpose:

```tsx
// src/app/(ko)/about/page.tsx                    // src/app/(en)/en/about/page.tsx
export const metadata = aboutMetadata("ko");      export const metadata = aboutMetadata("en");
export default function Page() { return <AboutPage locale="ko" />; }   … locale="en"
```

Pages are **not forked**: `components/pages/*` + the section components in `components/*` take a `locale`
prop (default `"ko"`) and pick content/copy/links from it. Segment config (`ensureStatic`,
`generateStaticParams`, `generateMetadata`) must be exported from the route file itself, so those stay there.

## How a page picks the locale

The route file passes it: `(ko)` pages pass `"ko"`, `(en)/en` pages pass `"en"`. Server components pass `locale`
down as a prop. Client components (header, cookie banner, forms, hero) also take `locale` as a prop; they must not
infer it from the URL except the language switcher, which uses `usePathname()` to find the same page in the other locale.

## Three kinds of strings, three places

| What | Where | Access |
| --- | --- | --- |
| Site data (site info, nav, divisions, projects, notes/blog posts, FAQs) | `src/lib/content.ts` (ko) / `content.en.ts` (en) | `const { site, divisions } = await getSiteContent(locale)` (defaults + admin overrides); `getContent(locale)` for non-text constants |
| Component/page UI copy | `components/<feature>/copy.ts` (ko, source of truth) + `copy.en.ts` (en, same shape) | `getHomeCopy(locale)`, `getAboutCopy(locale)` … exported from `copy.en.ts`; sections read them through `await getCopy(key, locale, …)` (`components/<area>/load.ts`) so admin overrides apply |
| Praise Tool product copy | `lib/praise-tool.ts` + `lib/praise-tool.en.ts` | `getPraiseToolCopy(locale)` (`getPraiseTool(locale)` = code defaults) |
| SEO titles/descriptions | `components/seo/seo-copy.ts` (registry docs `seo.*`), used by the page modules' `xMetadata(locale)` | edit there or in `/admin/content` |
| Header/footer/cookie banner/legal labels/404 | `components/chrome/copy.ts` + `copy.en.ts` | `getChromeCopy(locale)` |
| Privacy policy, terms, cookie policy | `components/legal/{privacy,terms,cookies}.copy.ts` + `.en.ts` | `getLegalDocCopy(kind, locale)` |

Internal links never hard-code `/en`: write the Korean path from `components/experiments/paths.ts` and wrap it:
`localePath(locale, PROJECTS_PATH)`, `projectHref(slug, locale)`, `contactHref(locale)`. `localePath("en", "/#contact")`
→ `/en#contact`; anchors (`#x`), `mailto:` and `https:` are left alone.

## How to add or change a string

1. Add the key with the Korean text to the feature's `copy.ts` (it is `as const`; functions are fine for plurals/placeholders).
2. Open `copy.en.ts` next to it. `copy.en.ts` is typed `Dict<typeof koCopy>`, so TypeScript fails until the same key exists.
   Add the English text. While untranslated, point at the Korean value and tag it:
   `title: aboutCopy.hero.title, // TODO(en)`.
3. Use it in the component via the accessor (`const C = getAboutCopy(locale)`), not by importing the Korean const.
4. New data (a project, a post, an FAQ)? Add it to `content.ts`, then give `content.en.ts` its English fields. Slugs, hrefs,
   URLs, image paths, numbers and dates must be identical across locales.
5. New page? Create `components/pages/<name>.tsx` (`<name>Metadata(locale)` + `<Name>Page({ locale })`, use
   `pageMetadata({ …, path, locale })` with the **Korean** path, and localize paths passed to JSON-LD with `localePath`), then two thin
   route files under `(ko)` and `(en)/en`, then add the path to `sitemap.ts`. To make its text editable in the admin, add a registry entry (docs/admin-content.md).

Find what is left: `grep -rn "TODO(en)" src docs`.

## SEO

- `lib/seo.ts` `locales` lists ko and en. `languageAlternates(path)` gives hreflang `ko`, `en`, `x-default` (= Korean).
- `pageMetadata({ path: "/about", locale })` emits `canonical` for that locale and `alternates.languages`; noindex pages
  (`/privacy/request`, `/unsubscribe`) emit no alternates. `og:locale` is `ko_KR` / `en_US`.
- `sitemap.ts` emits every public page twice (Korean, then `/en`), each with the full `alternates.languages` set.
- `robots.ts` disallows `/en/privacy/request` and `/en/unsubscribe` as well (`NOINDEX_PATHS`).
- JSON-LD builders in `lib/structured-data.ts` take `locale` (inLanguage, localized URLs, one `WebSite` node per locale;
  `Organization`/`Person` share their `@id`).
- Why the OG/Twitter card files sit outside the route groups: files inside a group get a hash suffix
  (`/about/opengraph-image-1v9je3`) and the old URLs would change. Outside the group the URLs stay as they were;
  `pageMetadata` therefore sets `openGraph.images` / `twitter.images` explicitly (Korean: the page's own card, English: `/en/opengraph-image`).
- `/en/llms.txt` exists (English index). Korean only: `llms-full.txt` and `insights/rss.xml`. English subpages share one generic OG card
  (`app/en/opengraph-image.tsx`); a post's own share image overrides it.

## Translation status

The English version is complete for all public pages, forms, legal documents and chrome. What is left is marked `TODO(en)` in code
(`grep -rn "TODO(en)" src docs`): per-page English OG cards, an English RSS feed (not advertised until English posts exist), and any string
that still points at the Korean value.

Rules for translators: keep keys, function signatures and `{placeholders}`; keep prices, dates and facts identical to the
Korean source; Korean uses 해요체 per `docs/copy-guide.md`; English should be plain and direct, no marketing superlatives.
`docs/copy-guide.md` still governs the Korean copy.
